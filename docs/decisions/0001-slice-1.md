# 0001: Slice 1 shape

Status: accepted

## Decisions

1. **Running it.** A command you run by hand. No server yet.
2. **Language.** TypeScript for the core and all plug-ins.
3. **Plug-ins.** Code modules that follow a small shared contract, all running in one program.
4. **Scope.** Take one GitHub issue, run Pi on it in a separate git worktree, and open a PR. Producer never merges; a human reviews.
5. **Config.** A `.producer/` folder in each project holds config and anything else Producer needs. Slice 1 sets only `tracker` and `harness`.
6. **Harness call.** Start `pi -p "<prompt>"` as a child process inside the worktree. Any harness with a CLI can plug in the same way.
7. **Target repo.** Slice 1 runs against this Producer repo.
8. **Picking the issue.** Passed by hand: `producer run <issue-number>`.
9. **Committing.** Producer commits after the harness exits, so it doesn't depend on how each harness behaves.
10. **Prompt.** The issue title and body wrapped in a short template: implement it, run the tests, don't push.
11. **Tracker access.** The `gh` CLI, using its existing login. A GitLab adapter would use `glab` the same way.
12. **Run record.** Each run writes `.producer/runs/<id>.json` in the target repo: issue, branch, harness output, result.
13. **Failures.** Fail hard. If the harness errors, changes nothing, or the branch already exists, Producer opens no PR, writes the reason to the run record, and exits non-zero.
14. **Harness permissions.** Pi runs with its defaults inside the worktree. To be tightened later.
15. **Tooling.** npm and Vitest.

## Deferred

- GitLab tracker.
- Other harnesses.
- Octokit and Gitbeaker adapters in place of the CLIs.
- Memory (see [vision](../vision.md#memory)).
